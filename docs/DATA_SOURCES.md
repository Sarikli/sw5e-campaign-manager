## 2. Findings: current module (`sw5e-module`)
- **Purpose:** a module layered on Foundry VTT's `dnd5e` system (README: targets Foundry v13, dnd5e 5.2.5). Patches dnd5e at runtime with `lib-wrapper`. Heavily Foundry/dnd5e-specific; not directly reusable in a standalone app.
- **Code license:** `LICENSE` = MIT ("Copyright (c) 2020 Repository Owner"). Applies to the code. It does **not** by itself license game content, book text, art, or Star Wars IP.
- **Content packs** (YAML source under `packs/_source`, ~120 MB total packs). Approximate record counts (yml files incl. folder/feature records): character-classes 2022, species 1871, enhanceditems 1980, equipment 623, powers-maneuvers 610 (force-powers 244, tech-powers 243, maneuvers 123 incl. folder files), snv-monsters 517, starships 505, customization-options 428, monsters 281, feats 225, deployments 205, fistoscodex 192, monstertraits 146, veshs-galactic-holodex 122, drakes-shipyard 87, backgrounds 61, weaponproperties 46, armorproperties 30, conditions 20; plus journal packs (PHB, Expanded Content, Wretched Hives, Mandalorian Codex).
- **Classes present:** berserker, consular, engineer, fighter, guardian, monk, operative, scholar, scout, sentinel (10).
- **Record format:** Foundry documents (dnd5e `spell`/`class`/`feat`/`loot` items with `system.*`, activities, `flags.sw5e-importer`, Foundry `_id`/`_stats`/`_key`). Powers are `type: spell` with `consume.target: powercasting.force.points.value` (so powers cost **force/tech points**, a distinct mechanic from D&D spell slots). Records carry an importer uid (e.g. `Power.name-agile_defense.level-1`) and `source.custom` (e.g. `EC` = Expanded Content).
- **Mechanics notes (CLAUDE.md):** single custom item type `maneuver`; starships are stock `vehicle` actors identified via flags; deployments/ventures modeled as feats; power-point computation in `scripts/patch/powercasting.mjs`.
- **Provenance:** records were generated by an importer (version 3, 2023) from the SW5e parser output; book journals generated from `StarWars5e.Core` parser sources.
- **ATTRIBUTION.md (verbatim concerns):**
  - Book text: "community SW5e reference material. Before redistributing modified or full-text journal exports outside this module's intended distribution channel, confirm upstream and SW5e community licensing expectations."
  - Starship art: "Maintainers should confirm and document original art sources, creators, and license terms … does **not** assert third-party copyright clearance."
  - Some art is stated as unofficial fan-made replacement art "not licensed, approved, or endorsed by Disney or Lucasfilm" (module.json).
  - The module is deliberately **not listed** on Foundry's repository "because it contains homebrew content" (README).

## 3. Findings: legacy system (`sw5e`)
- Foundry *system* (full system, GPLv3 `LICENSE`). README: "The software component of this system is distributed under the GNUv3 license." Content licensing not stated.
- Superseded by the module; use only for historical comparison. **GPLv3 code must not be copied into this app** unless we deliberately adopt GPLv3 for the app (not decided; avoid).
- Its game-icon SVGs have a separate `static/icons/LICENSE` (referenced by module ATTRIBUTION; not reviewed).

## 4. License analysis
| Asset | Status | Can we bundle? |
|---|---|---|
| Module source code (MIT) | Permissive | Could be read for ideas; we are not porting it (Foundry-specific). If any snippet is ever reused, retain MIT notice. |
| Legacy system code (GPLv3) | Copyleft | **No** (would impose GPLv3 on the app). Reference only. |
| SW5e rules text, class/species/power descriptions, tables | Community fan content derived from WotC-published 5e material and Star Wars IP. Redistribution terms **not established**. | **No** — not until permission/terms are confirmed in writing from SW5e maintainers; underlying IP (Lucasfilm/Disney, WotC) is a separate issue. |
| Names/terms (e.g. "Force", species names) | Star Wars trademarks/IP | Using names inside user-visible data is a risk; discuss with counsel. Game *mechanics* facts (numbers) are generally less protected, but this is a legal question — unresolved. |
| Art/icons/tokens | Provenance explicitly unconfirmed | **No.** Original art only. |
| `sw5e.com` website data/API | Terms unread | **No scraping/bundling** until terms are read and permission is obtained. |
| dnd5e SRD-derived material embedded in module data | Underlying license (SRD CC-BY-4.0 / OGL) not verified for these records | Unknown; do not rely on it. |

**Conclusion: redistribution rights for official SW5e content are NOT established. The repository's MIT license does not grant them.**

## 5. Content strategy (recommended)
1. **Schema first, content later.** Build the content model, pack format, validator and compendium over the pack format (Phase 2) using **original, clearly-licensed sample content** (e.g. a tiny invented "demo" pack, clearly labeled) for tests.
2. **User-imported content packs.** Users may import a pack file they obtained themselves. The app stores it locally, tagged `origin='user_import'`, with provenance/attribution fields; the app does not ship or host it. (Residual legal question: providing an *importer for a specific third-party format* — review with counsel.)
3. **Permission track (in parallel, owner action):** contact the SW5e maintainers (and consider Lucasfilm/WotC policies) to request written permission/terms for bundling content with attribution.
4. **Never invent content** to fill gaps; the engine stays data-driven so missing content is simply absent.
5. The rules *engine* implements mechanics (formulas like ability modifier), which must be verified against sw5e.com and documented in RULES_ENGINE.md.

## 6. Pack format requirements (for Phase 2)
Each pack declares: `pack_id`, `namespace`, `name`, `publisher`, `rules_version`, `data_version`, `license` (SPDX or text), `attribution`, `source_url`, `origin`, entries with stable ids `<namespace>:<type>:<slug>`, `source_ref`, `prerequisites`, `properties` (typed per content type), `is_custom`. Validated by Zod; checksum recorded; versioned upgrade policy: packs are immutable per `data_version`; upgrades install a new version and characters record the version they were built on.

Mapping of required categories → evidence in the module (to verify against sw5e.com in Phase 2): species ✔ (species packs), classes ✔ (10), archetypes ✔ (class subfolders), backgrounds ✔, feats ✔, fighting styles/class features ✔ (class-features), force/tech powers ✔, maneuvers ✔ (custom item type), weapons/armor/equipment ✔, weapon/armor properties ✔, enhanced items ✔, customization options ✔, monsters/NPCs ✔, conditions ✔, starships ✔ + deployments/ventures ✔ + starship equipment/modifications (to verify), vehicles (to verify), rules/variant rules (journals), tables ✔. Existence of a data category in the module does **not** mean we may ship it.

## 7. Trademark and identity
- No Star Wars, Lucasfilm, Disney, WotC or SW5e logos, art, fonts, or trade dress.
- App name: avoid "Star Wars"; "SW5e" in the *name/bundle id/store title* carries trademark/store-review risk. **Decision required** (see ROADMAP open issues). Working codename: "SW5e Companion". Descriptive reference ("compatible with SW5e") in the description may be acceptable but needs review.
- Required About screen text: unofficial fan tool; not affiliated with or endorsed by SW5e, Lucasfilm, Disney or Wizards of the Coast; list of attributions per installed pack.
